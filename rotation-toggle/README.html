把屏幕方向的控制权从系统手里拿回来。一个不联网、不收集数据、专注做一件事的 Android 小工具。

一、这是什么 ​

Android 自带的方向控制在很多场景下并不好用：躺在被窝里刷手机，系统把屏幕翻成侧面的横屏；平板挂在支架上，轻微倾斜就来回乱转；某些应用自作主张锁定方向，你又改不回来。

一键转屏就是为这些场景做的。它提供四种层次的控制能力，从「跟着系统走」到「彻底锁死一个方向」，把选择权交回给用户。

三、安装 ​

  1. 下载 一键转屏_v1.2.apk 并传到设备，点击安装。
  2. 若提示「未知来源」，前往 设置 → 应用 → 特殊权限 → 安装未知应用，允许你所用的文件管理器安装。
  3. 安装完成后，桌面会出现「一键转屏」图标。

从旧版本升级：直接覆盖安装即可，签名相同，数据与设置不受影响。

关于安全提示：由于是本地自签名，部分系统会提示「证书链无效」或「来自未知开发者」。这是自签证书的固有现象，不影响功能。请确认 APK 的 MD5 与上表一致后再安装。

四、界面与首次授权 ​

打开应用后，顶部会显示一行权限状态，形如：

通知权限 ✓ 已授予　|　root ✓ 已授权　|　后台 ✗ 未保活

状态行显示三项，另有一项「修改系统设置」以提示条形式单独引导。各授权项说明如下：

授权项必要性说明
修改系统设置必需没有它，本应用无法写入任何旋转参数，所有按钮都会失效。点击界面上的提示条即可跳转开启。
通知权限建议用于快捷磁贴与状态提示。不给也能用，只是磁贴反馈会变弱。
允许后台运行建议豁免电池优化，防止熄屏后被系统冻结。若你使用「强制传感器」系列功能，强烈建议开启，详见第六章。
root可选有 root 时走 wm 命令，可以真正锁死方向；无 root 时退化为系统设置接口，功能覆盖略窄。

页面整体结构自上而下为：

  1. 权限状态行 —— 实时反映三项授权情况；
  2. 方向按钮区 —— 四个普通切换按钮 + 自动旋转 + 顺时针 90°；
  3. 锁定功能组 —— 传感器区间锁定、固定方向锁定、解除所有锁定；
  4. 快捷入口区 ——「申请通知权限」「允许后台运行」；
  5. 说明区 —— 页面内嵌的使用说明与保活提示；
  6. 页脚 —— 显示当前版本号与可点击的项目地址。

五、功能详解 ​

5.1 普通切换（跟随系统设置） ​

界面最上方一排四个方向按钮：

  • 竖屏 / 横屏 / 反向竖屏 / 反向横屏

行为特点：只写入 user_rotation，不改动 accelerometer_rotation。也就是说，如果你原本开着自动旋转，切换后系统仍会在你倾斜设备时接管。适合「临时捅一下方向」的场景。

5.2 自动旋转（重力感应） ​

一键恢复系统的重力感应旋转。等价于把方向控制权交还给传感器。

5.3 顺时针转 90 度 ​

每次点击让当前方向顺时针跳一格（0° → 90° → 180° → 270° → 0°）。适合单手快速翻转，或给没有方向键的场景用。

5.4 传感器区间锁定 ​

按钮：强制传感器横屏 / 强制传感器竖屏

这是本应用区别于普通转屏工具的核心功能。它仍然跟着重力走，但限定在一个区间内翻转，不会转到区间外：

  • 倾角阈值 0.75：当设备倾斜超过该比例才判定为「想换向」，避免平放时的抖动误判。
  • 稳定判定 400 ms：新方向需要持续稳定一段时间才生效，抖动会被过滤掉。
  • 主导比例 1.15：两个轴的加速度需要拉开差距才认定方向，进一步抑制临界角抖动。
  • 横屏区间只会在「横屏 ↔ 反向横屏」之间切换；竖屏区间只在「竖屏 ↔ 反向竖屏」之间切换。永远不会跨区间。

适合躺床上刷手机、平板挂在支架上等场景。

该功能依赖重力传感器持续回调，务必配合第六章的「允许后台运行」，否则熄屏后可能失效。

5.5 固定方向锁定（死锁一个方向） ​

按钮：固定横屏 / 固定竖屏 / 固定反向横屏 / 固定反向竖屏

彻底锁死一个方向。此后：

  • 重力感应失效，怎么倾斜都不动；
  • 自动旋转开关被关闭；
  • 第三方应用的自定义方向请求也会被覆盖（有 root 时效果最强）。

有 root：通过 wm fixed-to-user-rotation 实现，属于系统级锁定。 无 root：仅能写入常规旋转参数，部分顽固应用可能仍会强改方向。

5.6 解除所有锁定 ​

一次性清空本应用写入的所有旋转参数，把控制权完整交还系统：

  • 清除固定方向（有 root 时会解除 fixed-to-user-rotation）；
  • 恢复 accelerometer_rotation = 1（自动旋转开启）；
  • 清除本应用记录的状态。

无 root 时，如果之前用过「固定方向锁定」，系统层面可能残留 fixed 状态，解除后需重启一次设备才能完全恢复。

5.7 快捷入口 ​

页面底部「— 快捷入口 —」区域提供两个按钮：

  • 申请通知权限：引导开启通知权限。
  • 允许后台运行：引导豁免电池优化。

另外仍有快捷设置磁贴：下拉通知栏 → 编辑磁贴 → 拖入「一键转屏」，可在任意界面快速切换。

六、为什么需要「允许后台运行」 ​

这是 v1.2 的核心修复。

问题现象：切到后台或熄屏一段时间后，方向锁定失效，必须切回前台一次才恢复。

真正原因：不是进程被杀，也不是通知丢失。Android 的 Cached App Freezer（缓存应用冻结） 会在熄屏后把后台进程整体冻结，CPU 直接停机，表现为 /proc/<pid>/status 里的 do_freezer_trap。冻结期间重力传感器的回调完全停摆，应用收不到任何姿态变化，屏幕就停在旧方向。切回前台时进程解冻，传感器回调恢复，方向立刻被纠正——这就是「切前台一次就好了」的来源。

关键认知：前台服务和常驻通知只能防止进程被杀，防不住进程被冻结。两者的机制不同，所以「已锁定后台」「通知一直都在」并不足以解决问题。

解决方法：让应用进入电池优化白名单（deviceidle whitelist）。

操作步骤 ​

  1. 打开应用，滚到底部「— 快捷入口 —」，点 允许后台运行。
  2. 系统弹出「允许应用在后台运行？」对话框 → 选择 允许。
  3. 返回应用，顶部状态行应变为 后台 ✓ 已保活。

如果没弹出对话框 ​

小米 / HyperOS 部分版本会拦截直达请求，此时会退化为打开电池优化列表页，请手动找到「一键转屏」并设为允许。

若仍未生效，手动路径为：

设置 → 应用 → 一键转屏 → 省电策略 → 选择「无限制」

设置完成后回到应用，状态行会自动刷新。

验证方法（进阶） ​

有 root 或 ADB 权限时，可以用命令确认白名单状态：

bash
adb shell dumpsys deviceidle whitelist | grep rot.toggle
# 正常输出：user,com.rot.toggle,10371

也可以观察进程是否被冻结：

bash
adb shell cat /proc/$(adb shell pidof com.rot.toggle)/status | grep State
# 正常为：State: S (sleeping)
# 若看到 do_freezer_trap，说明仍被冻结

关掉电池优化意味着系统不会为省电而冻结本应用，理论上会略微增加待机耗电。由于本应用本身几乎不耗电（仅监听传感器），实际影响很小。

七、常见问题 FAQ ​

Q1：点了按钮没反应？ 先看顶部状态行。「修改系统设置」未授权时，所有写参数的操作都会失败。这是绝大多数「点了没反应」的原因。

Q2：切到后台或熄屏后就失效，切回前台才好？ 典型的进程冻结，见第六章。注意「锁定后台」「常驻通知」都不能解决这个问题。

Q3：为什么有些应用（游戏、视频）还是会强行改方向？ 它们调用 setRequestedOrientation 主动指定方向，优先级高于普通设置写入。无 root 时难以阻止；**开启 root 并使用「固定方向锁定」**可以应对绝大多数情况。

Q4：状态行显示 root ✗ 未授权，但我已经装了 KernelSU？ 打开 KernelSU 管理器，在「超级用户」列表里找到「一键转屏」并授权。回到应用后状态行会自动刷新（或切前台一次）。

Q5：快捷磁贴点了没变化？ 磁贴反馈依赖通知权限。若未授权通知，磁贴仍会执行操作，但可能没有文字反馈。

Q6：卸载后方向还是锁着？ 说明卸载前没执行「解除所有锁定」。重启设备即可恢复。

Q7：支持 Android 7 及以下吗？ 不支持。最低 API 26（Android 8.0），因为前台服务与通知渠道的实现在此版本之后才有稳定行为。

Q8：会不会收集我的数据？ 不会。应用没有 INTERNET 权限，也无法联网。整个 APK 只有 22 KB，不含任何第三方库。

八、注意事项 ​

  1. 第三方应用的自定方向无法 100% 覆盖。有些应用（尤其是游戏、视频播放器）会调用 setRequestedOrientation 强行指定方向，本应用在无 root 情况下难以阻止——这是 Android 的权限设计决定的，不是 bug。
  2. Android 12+ 的「固定应用方向」开关会冲突。若系统设置里开了「固定应用方向」，可能与本应用争夺控制权，建议关闭它。
  3. 点了没反应？先查权限。绝大多数失败都是因为「修改系统设置」权限没给。界面顶部会显示权限状态，若显示未授予，点一下跳转开启。
  4. 秒失效？查后台保活。若切后台或熄屏后失效，检查顶部状态行是否显示「后台 ✗ 未保活」，按第六章设置。
  5. 卸载前请先点「解除所有锁定」。否则残留的 fixed 状态可能在卸载后依然生效，届时只能重启设备恢复。

九、卸载 ​

  • 常规方式：长按图标 → 卸载，或 设置 → 应用 → 一键转屏 → 卸载。
  • 推荐顺序：先打开应用点「解除所有锁定」→ 再卸载。
  • 卸载时可勾选清除数据，本应用不保存任何用户数据，勾不勾都一样。
  • 卸载后若之前加过电池优化白名单，该记录会随应用一并移除，无需手动清理。

十一、技术细节 ​

写给想了解实现或参与改进的人。

方向控制的四条路径 ​

路径方式权限要求强度
系统设置接口Settings.System.putInt(USER_ROTATION)WRITE_SETTINGS弱，应用可覆盖
ADB 级命令wm user-rotation lock Nroot / shell中
系统级固定wm fixed-to-user-rotation enabled Nroot强
传感器锁定监听 SensorManager + 动态写入WRITE_SETTINGS中，可跟随姿态

传感器锁定的判定逻辑 ​

读取加速度计 x / y 轴
  → 计算倾斜比例
  → 超过 FLAT_RATIO (0.75) 视为「想换向」
  → 检查主轴与副轴的比值是否超过 DOMINATE_RATIO (1.15)
  → 目标方向需稳定 SETTLE_MS (400ms)
  → 与系统真实 user_rotation 比对，不同则写入

关键设计：每次都读取系统真实的 user_rotation 作为基准，而不是维护内部状态。这样即使其他应用改了方向，本应用也能在下次回调时纠正回来。

保活实现 ​

  • 前台服务（foregroundServiceType="specialUse"），START_STICKY 防杀；
  • 通过反射调用 PowerManager.isIgnoringBatteryOptimizations() 检测白名单状态（为兼容老 API 编译环境，未直接引用新符号）；
  • 引导跳转采用三级降级：REQUEST_IGNORE_BATTERY_OPTIMIZATIONS 直达 → 电池优化列表页 → toast 引导 HyperOS 手动路径。

构建环境 ​

  • 纯命令行构建，无 Gradle；
  • aapt2 编译资源 → javac（source/target 8）→ d8（min-api 26）→ jarsigner；
  • 目标桩 android.jar 为较老版本，故所有 API 20+ 符号均通过反射或字面量常量访问。
